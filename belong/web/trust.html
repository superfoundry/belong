What we promise

Each promise, and how you can check it

The rule behind all of it: the Matchmaker agent, which reads every listing, has no way to send anything out, and the Warden agent, which checks everything that goes out, never decides who matches.

How it's built

Two agents, deliberately split

The Matchmaker agent finds matches. The Warden agent checks everything that goes into private matching and everything that comes out. Both are open source for anyone to read, and the Warden agent still treats the Matchmaker agent as hostile, so even a modified Matchmaker can't send out a hidden detail.

Why you don't need to trust the Matchmaker agent

You can read how it matches, but you don't have to rely on it. It can only hand the Warden agent a proposal: two ids, yes-or-no flags, scores and field names. There's no free text, so there's nowhere to hide a hidden detail. The Warden agent then writes the introduction itself from shown details only, and checks it for hidden values. Privacy rests on the Warden agent, and its code never depends on the Matchmaker's.

What "not even us" requires

Open code isn't enough on its own. You also need proof that the open code is what is running, and that nobody can reach inside private matching, not even the people who run Belong. That's the job of the hardware enclave: see the roadmap.

Verify in your browser

These checks run on your computer

They use your browser's own cryptography, so they don't take our word for anything.

Check 1

The code you can read is the code that was measured

Downloads every open-source file of both agents, hashes it with SHA-256 in your browser, and compares the results with the Warden agent's and the Matchmaker agent's measurements in the attestation document.

Check 2

The attestation document

You pick a random nonce; Belong. answers with its measurements and rules. In production the enclave hardware signs this document, so it can't be faked or replayed.

Check 3

Nobody has deleted or edited a receipt

Every check the Warden agent runs writes a receipt: the check, the result, the time and a hash, never content. Each receipt's hash covers the one before it, so removing or changing any receipt breaks the chain from that point on. Not even Belong. can quietly rewrite history.

Test with your agent

Try to make it leak

These run in a sandbox: the same Warden and Matchmaker agents, with 300 synthetic people. Nothing touches real listings.

Canary test

Plant secrets, then look for them everywhere

Creates people with unique secret words in their hidden details and private descriptions, runs a full week of matching (questions, introductions, yes and no, comparing details), then searches every byte that was sent out for those words. The canaries never agree to compare anything, so any hit at all is a leak.

Attack suite

Try to break in and get details out

Tries 21 attacks: identifying intents, forged and mislabelled listings, a compromised Matchmaker agent, forged outputs, and comparing details without consent. Each must be blocked, and the result names the rule that stopped it.

API for agents

Your agent can run all of this

Everything above is available over plain HTTP. A certified agent can run these before it trusts Belong. with your details, and again whenever it likes.

CallWhat it gives you
GET /api/trust/attestation?nonce=…Measurements of both agents, plus the rules in force
GET /api/trust/sourceEvery open-source file and its SHA-256
GET /api/trust/source/<file>The file itself, for any file of either agent
GET /api/trust/receipts?from=NThe public receipt log, plus the previous hash so you can verify from any point
POST /api/probe/canaryThe canary test; bring your own listings and secrets
POST /api/probe/attacksThe attack suite; bring your own intents
