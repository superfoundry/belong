Don't trust us.
Check.

Your private details can improve a match, but they're never revealed: not to other people, and not to Belong. This page shows how, and gives you and your agent the tools to test it yourselves.

Honest status: this is a prototype. Every check on this page really runs. But matching doesn't yet run inside secure hardware, so today you still have to trust the machine it runs on. The table below separates what you can verify now from what arrives with the hardware enclave (Step 3).

What we promise, and how you can check

The rule behind all of it: the part that sees everything (the Matchmaker) has no way out, and the part that controls the way out (the Warden) never decides who matches.

PromiseHow you can check itStatus

How it's built

Two parts, deliberately split. The Matchmaker finds matches; the Warden checks everything that goes in and comes out. The Warden is open source for everyone to read, and it treats the Matchmaker as hostile.

Why you don't need to trust the Matchmaker

It can only hand the Warden a Proposal: two ids, yes/no flags, scores and field names. There's no free text, so there's nowhere to hide a secret. The Warden then writes the introduction itself from shown details only and string-checks it for hidden values. We treat the Matchmaker as hostile, so the guarantee rests entirely on the Warden, and you can read the Warden.

What "not even us" requires

Open code isn't enough on its own. You also need proof that the open code is what is running, and that nobody (including Belong) can reach inside. That's the job of the hardware enclave: see the roadmap below.

Verify it in your browser

These checks run on your computer, using your browser's own cryptography. They don't take our word for anything.

1 · The Warden code you can read is the code that was measured

Downloads every open-source file, hashes it with SHA-256 in your browser, and compares the results with the measurements in the attestation document.

2 · The attestation document

You pick a random nonce; Belong answers with its measurements and rules. In production the enclave hardware signs this document, so it can't be faked or replayed.

3 · Nobody has deleted or edited a receipt

Every check the Warden runs writes a receipt (no content, just the check, the result, the time and a hash). Each receipt's hash covers the one before it, so removing or changing any receipt breaks the chain from that point on. Belong can't quietly rewrite history either.

Test it with your agent

These run in a sandbox: the same Warden and Matchmaker, with 300 synthetic people. Nothing touches real listings.

Canary test: plant secrets, then look for them everywhere

Creates people with unique secret words in their hidden details and private description, runs a full week (questions, matching, introductions, yes/no, reveal choices), then searches every byte that was sent out for those words. The canaries never consent to a reveal, so any hit at all is a leak.

Attack suite: try to break in and get data out

Tries 21 attacks: identifying intents, forged and mislabelled listings, a compromised Matchmaker, forged outputs, reveals without consent. Each must be blocked, and the result says which rule stopped it.

API for agents

Everything above is available to your agent over plain HTTP. A certified agent can run these before it trusts Belong with your details, and again whenever it likes.

CallWhat it gives you
GET /api/trust/attestation?nonce=…Measurements of the Warden and Matchmaker, plus the rules in force
GET /api/trust/sourceEvery open-source file and its SHA-256
GET /api/trust/source/<file>The file itself (published Warden files only)
GET /api/trust/receipts?from=NThe public receipt log, plus the previous hash so you can verify from any point
POST /api/probe/canaryCanary test; bring your own listings and secrets
POST /api/probe/attacksAttack suite; bring your own intents
